## 核心定位

HAD 和 SR3M 合并为一篇论文：SR3M 提出问题（地形 benchmark），HAD 的双视角融合给出答案。

论文故事：

1. 现有无人机 VLN benchmark 虽然包含自然地貌，但没有把地形复杂度作为核心变量来研究
2. SR3M 共 8 个场景 × 4 张地图 × 约 50 条轨迹（约 1,600 条）。有地形起伏的是 mountain 和 desert 两个场景：mountain 201 条路线按 AGL 分层，125 条指令要求随地形调整高度；desert 在 Blender 中按 mountain 的设计重建 4 张起伏地图，与其他场景一样 3 张进训练、1 张整图留出作未见地图评测
3. 实验发现（10/27，val_unseen，见下文"已确立的结论"）：在未见地形上调整高度很难，所有方法只跟上约一半的地形起伏；加入俯视角让随地形路线的高度误差下降 14.7%，只看俯视就优于只看前视
4. 俯视角提供的是沿航向前方的地形起伏（与尺度无关的坡度）；离地高度本身对每步高度动作没有贡献。这一信息只有 3D 感知强的编码器（DINOv2）才读得出来，ResNet 读不出，会掩盖俯视的价值
5. 简单的双视角融合基线（HAD）验证这一点，并暴露出一个 benchmark 层面的问题：模型几乎不使用指令里的"随地形 / 定高"条件，用成对路线加反事实指令互换可以直接测出；竞品的双视角融合方式在同一框架下复现对比

原计划的第 3 点"地形越复杂，俯视帮助越大"（H2）两次都未获统计支持，不作主张。

注意：多视角输入本身不新，OpenUAV 已经默认配置了 5 个视角；前视 + 俯视双视角也已有直接竞品（见下文"相关工作与竞品基线"）。

论文定位（10/25 决定 D2）：**benchmark + 地形分析为主**。卖点是"俯视角在什么情况下有用、和地形与离地高度是什么关系"的分析，加上以地形为核心的 benchmark；已查到的竞品都没有做这一分析。HAD 定位为简单、强的双视角基线，不主张方法新颖性。

模型路线：冻结视觉骨干 DINOv2-B（10/27 起，protocol.md §11）+ HAD 轻量策略头（简单拼接，可训练部分不到 1/10），ResNet 版作为对照报告；不再写"可机载部署"，除非补测机载推理速度。VLM 只作为零样本基线，通过 API 调用。

## 已确立的结论（10/27）

详见 `runs/terrain_v2_dino/decision/onepage.md`、`dino_results.md`。

| 可以主张 | 证据（val_unseen，三种子） |
| --- | --- |
| 加入俯视降低随地形路线的高度误差 | H1 14.7%，CI [9.9, 19.2] |
| 只看俯视优于只看前视 | S2 11.5%，CI [5.7, 16.8] |
| 更强的编码器放大俯视的帮助 | S1：ResNet 4.8% → DINOv2 14.7%，差 +10.0%，CI [5.3, 14.7] |
| 模型不用指令里的高度条件（benchmark 发现） | 反事实互换 β 只变约 0.07；反事实增广能修好服从性但牺牲跟随（R1） |

| 不能主张 | 原因 |
| --- | --- |
| 地形越陡，俯视越有用 | H2 两次未过（DINOv2：高坡 18.1% vs 低坡 9.4%，差值 CI 跨 0） |
| 俯视对定高路线无害 | 对照组 +2.4 cm，集中在 1 条断崖定高路线（B 跟着地形爬升） |
| 俯视改善水平导航 | 离线沿专家轨迹时，不看图的 N 在转弯/STOP 上与视觉模型接近，需闭环检验 |
| 单目做不到高度控制 | oracle 拆分表明所需的是与尺度无关的坡度，原则上单目可得 |

## 11/10 决策标准

在 val_unseen 的留出地图上（mountain 与 desert 各 1 张），比较 A（仅前视）和 B（前视 + 俯视）。判据在开训前固定，细节见 [protocol.md](protocol.md) §6。

| 结果 | 结论 | 下一步 |
| --- | --- | --- |
| H1：随地形路线上 B 的相对 dz 改善（1 − B/A）三个种子都为正，路线配对 95% CI 下界 > 0；H2：高坡段的相对改善大于低坡段；对照路线 B 不比 A 差超过 1cm | 核心假设成立 | 继续主线，冲 RA-L + IROS |
| 只有 H1 成立 | 俯视有用，但"越复杂越有用"未获支持 | 继续主线，主张限定为"地形跟随受益于俯视" |
| H1 不成立 | 双视角故事不成立 | 转向 benchmark 论文：系统评测现有方法在不同地形条件下的表现，HAD 作为基线；目标改为 Drones 等期刊 |
| 离线评测中 yaw 预测已塌缩成直飞 | 模型本身有问题 | 无论哪条路，接入闭环前必须先解决 |

**实际结果**：ResNet（10/25）与 DINOv2（10/27）都落在"只有 H1 成立"，且对照组受损（规则输出"先查融合"）。按此继续主线，主张限定为"地形跟随受益于俯视"；融合问题排查后写成发现。yaw 未塌缩（转弯 yaw 误差约 1.4°，固定直飞 2.8°）。

不再用"125 条的提升大于 76 条"作判据：mountain 对照组全是平地定高路线，dz 几乎为 0，这个比较没有区分力。

## 可选支线：生成式外观增强与真实测试集

优先级低于沙漠重建，有余力再做，不阻塞主线；12/15 前做不成就留给下一篇论文或期刊扩展版。

做法：以 UE5 渲染的深度图、分割图或边缘图为条件，用生成模型只改变外观纹理、保留几何结构。只对一小部分帧做增强。位姿、动作、指令沿用仿真数据，前视和俯视来自同一场景，几何一致。

论文里的说法："生成式外观增强"，作为提升视觉鲁棒性的方法模块。生成图像必须明确标注为生成图像，不能称为真实图像。

结论的边界：

- 有真实测试集（几十条带图像、位姿、指令的轨迹）→ 可以声称提升了真实世界泛化能力
- 没有真实测试集 → 只能声称提升了对外观变化的鲁棒性

候选真实数据：UAV-Flow、AirNav 等公开真实无人机数据集；它们以城市场景为主，视角和地形是否匹配需要逐个核实。真实数据离线评测本身已转入主线（D3，见上一节）；这里只剩生成式外观增强，以及它在真实数据上的效果。
